# 🚗 Vehicle Damage Detection using YOLO26

An AI-powered Vehicle Damage Detection System built using YOLO26, Computer Vision, Deep Learning, Python, Flask, HTML5, CSS3, and JavaScript.

This project detects visible vehicle damage from uploaded images using a trained YOLO26 object-detection model and presents the results through a professional, responsive, premium dark-themed web application.

---

## 📌 Overview

Vehicle damage inspection is an important application in the automotive, insurance, vehicle rental, repair, and fleet-management industries.

Traditional vehicle inspection often requires manual examination of vehicle images to identify damaged areas. This process can be time-consuming and may depend on human expertise.

This project demonstrates an AI-assisted approach using Deep Learning and Computer Vision.

The application allows a user to upload a vehicle image. The trained YOLO26 model analyzes the image and detects visible damage regions. The Flask backend processes the prediction and returns an annotated image along with detection information.

The complete process is:

    Vehicle Image
          ↓
    Image Upload
          ↓
    File Validation
          ↓
    Image Preprocessing
          ↓
    YOLO26 Inference
          ↓
    Damage Detection
          ↓
    Confidence Extraction
          ↓
    Bounding Box Annotation
          ↓
    Result Generation
          ↓
    Results Displayed

> This project is intended as an AI-assisted visual detection and portfolio demonstration system. It should not be considered a replacement for professional vehicle inspection, engineering assessment, insurance evaluation, or repair estimation.

### 6. Image Annotation

The YOLO prediction is plotted onto the image.

### 7. Result Generation

The backend prepares the detection information and annotated image.

### 8. Result Display

The result is displayed on the same `index.html` page.

## 📈 Model Performance

The available model evaluation results from the project training workflow are approximately:

| Metric | Score |
|---|---:|
| Precision | 0.689 |
| Recall | 0.511 |
| mAP@50 | 0.512 |
| mAP@50-95 | 0.308 |

### Precision

Precision represents the proportion of predicted detections that were correct.

### Recall

Recall represents the proportion of relevant damage instances that were successfully detected.

### mAP@50

Mean Average Precision calculated at an IoU threshold of 0.50.

### mAP@50-95

Mean Average Precision averaged across IoU thresholds from 0.50 to 0.95.

> Actual performance may vary depending on image quality, lighting, vehicle type, camera angle, damage visibility, dataset distribution, and deployment environment.

## 🧠 Why One Gunicorn Worker?

YOLO models can consume significant memory when loaded.

If multiple Gunicorn workers are used, each worker can load its own copy of the model.

Example:

    Worker 1 → YOLO26 Model
    Worker 2 → YOLO26 Model
    Worker 3 → YOLO26 Model

This can significantly increase RAM usage.

Therefore, this project uses:

    --workers 1

The configuration also uses:

    --threads 2

and:

    --timeout 120

This configuration is intended to be more suitable for memory-constrained CPU deployment environments.

## 🔧 Troubleshooting

### Model Not Found

If the application reports that the model cannot be found, verify:

    model/vehicle_damage_yolo26_best.pt

Check that:

- The `model` directory exists.
- The `.pt` file exists.
- The filename is correct.
- The model is included in the deployment repository.

### Application Does Not Start

Install dependencies again:

    pip install -r requirements.txt

Then run:

    python app.py

### Port Error

When deployed, the application uses the platform-provided `$PORT`.

Production command:

    web: gunicorn --bind 0.0.0.0:$PORT --workers 1 --threads 2 --timeout 120 app:app

### Out-of-Memory / SIGKILL

If the deployment environment terminates the Gunicorn worker because of memory usage:

1. Keep `--workers 1`.
2. Use CPU inference.
3. Keep image resizing enabled.
4. Avoid loading the YOLO model multiple times.
5. Consider a larger deployment instance if necessary.

### Logo Not Displaying

Verify that the logo exists at:

    static/images/logo.png

The Flask template should reference the image using Flask's static-file URL generation.
